Ветка `claude/analyst-calibration` (от `claude/integration` @ 260d31c). Все числа ниже взяты из
реальных прогонов 17–18.10.2026; сырые данные лежат в `docs/evidence/analyst-calibration/`.

## Что было не так

1. **Baseline перебивал факторы.** Сплит считался как `0.65·agent_net + 0.35·baseline_net`
   (с перенормировкой весов), где `baseline_net` доходил до ±1. В живом прогоне факторы дали
   6 long против 13 short (agent_net −0.37), baseline +1.00, итог +0.11 → 58% LONG, хотя сам
   агент сказал neutral. В выборке ниже тот же эффект повторился: BTC 15m, 5 long / 16 short,
   baseline +1.00 → по старой формуле 51/49 neutral.
2. **EMA не совпадали.** Снимок считал EMA 7/14/28, а лента EMA на графике по умолчанию
   7/14/21 и настраивается пользователем.

## Бэктест baseline (задача 3a)

`scripts/backtest_analyst.py` (stdlib + код репозитория): данные Binance USDT-M, на каждый
бар заново собирается `fetch_market`-словарь **только из свечей, закрывшихся к закрытию бара**
(`analyst_backtest.closed_upto`), прогоняется боевой `compute_confluence_score` +
`make_decision` (`analyst.baseline_section`) и оценивается правилом оценщика
(`analyst_store.evaluate_outcome`): +1 ATR14 в сторону наклона раньше −1 ATR против, в
пределах 12 баров графика.

- BTCUSDT, ETHUSDT, SOLUSDT; 15m за 90 дней (20.07–17.10.2026), 1h за 180 дней
  (21.04–17.10.2026); 38 778 оценённых баров, 36 705 решённых (остальное — таймаут/оба
  уровня в одном баре). Прогон ~3 мин.
- Базовая частота «сначала вверх»: 50.7% (95% CI 50.2–51.2%).

Попадание направления наклона baseline (старое правило: gain 2.0, verdict ±0.5), все бары:

| baseline_net | n | вверх / вниз первым | попадание (решённые) | 95% CI Wilson |
|---|---:|---:|---:|---|
| [−1, −0.5] | 10 095 | 4 844 / 4 820 | 49.9% | 48.9–50.9% |
| [−0.5, −0.2] | 5 127 | 2 486 / 2 286 | 47.9% | 46.5–49.3% |
| [−0.2, 0) | 4 949 | 2 381 / 2 269 | 48.8% | 47.4–50.2% |
| 0 | 177 | 94 / 64 | — | — |
| (0, +0.2] | 4 572 | 2 215 / 2 111 | 51.2% | 49.7–52.7% |
| [+0.2, +0.5] | 5 463 | 2 622 / 2 572 | 50.5% | 49.1–51.8% |
| [+0.5, +1] | 8 395 | 3 979 / 3 962 | 50.1% | 49.0–51.2% |

- Весь наклон вместе: **49.8% попаданий из 36 547 решённых (CI 49.3–50.3%)**. По отдельности:
  15m 49.8%, 1h 49.7%, BTC 49.9%, ETH 49.9%, SOL 49.5% — везде CI накрывает 50% или ниже.
- Сильный наклон не лучше слабого: монотонности по корзинам нет.
- Варианты правила дают то же: gain 1.0 / verdict ±0.25 — 49.8%; только счёт без verdict — 49.6%.
- Старое правило насыщалось: |baseline_net| ≥ 0.5 на 48% баров, ровно ±1 на 16%.
- Перекрытие горизонтов делает соседние бары зависимыми, поэтому CI выше оптимистичны; на
  непересекающейся подвыборке (каждый 12-й бар, n≈3 200) корзины 46–55% с CI ±3–5 п.п. —
  тоже без преимущества.

**Вывод:** у наклона baseline нет измеримого преимущества, поэтому он может быть только
маленьким тай-брейкером и не должен перебивать факторы.

## Живая выборка Hermes (задача 3b, только ориентир)

`backtest_analyst.py hermes --n 12`: 12 анализов Hermes (`hermes-agent`, 20–24 с каждый) на
прошлых закрытых барах 13–17.10 (BTC/ETH/SOL × 15m/1h), снимок собран как на момент
закрытия бара (`analyst_backtest.historical_snapshot`), затем оценён по следующим 12 барам.

- Восстановлено: свечи, индикаторы, структура, FVG, OB, сессия, ликвидность/HTF/режим/поток,
  baseline, последний **расчётный** funding Binance.
- Не восстанавливается и помечено в `missing`: контекст биржи (mark/index/OI), стакан,
  footprint, позиционирование, прогноз funding и кросс-биржевой funding.
- Итоги (11 направленных, 1 таймаут): старый сплит 4 win / 6 loss / 1 timeout / 1 neutral;
  новый 3 / 7 / 1 / 1; только факторы — 3 / 7; собственный bias агента — 3 / 8 / 1.
- Из 5 конфликтов факторы↔baseline первым пришло направление baseline в 3, факторов в 2.
- n слишком мало, бары из одного режима рынка за 5 дней — это не доказательство ни для
  факторов, ни для baseline. Выборка показывает только, что новый сплит не уходит против
  перевеса факторов. Откалиброванной вероятностью сплит не является.

## FIX 1: правило сплита (выбрано по данным)

`analyst.SPLIT_CONFIG` (с комментариями в коде):

```
agent_net    = Σ sign·strength / max(Σ strength, 6)
baseline_raw = clip(1.0·(L−S)/(L+S) ± 0.25 за verdict LONG/SHORT)      (было 2.0 и ±0.5)
baseline_net = clip(baseline_raw, ±0.5)                                  (новое: потолок)
w_b          = 0.1, но 0, если знаки разные и |agent_net| ≥ 0.15         (было 0.35)
net          = 0.9·agent_net + w_b·baseline_net   (без перенормировки)
если знак net противоположен знаку agent_net → net = 0
p_long       = logistic(3·net); |p_long − 50| < 5 → neutral
```

- Один baseline может сдвинуть p_long максимум на 3.7 п.п. (3·0.1·0.5 = 0.15 < logit 0.55),
  то есть из нейтральной полосы сам не выводит. Поэтому при отказе Hermes ответ всегда
  neutral с наклоном ≤ 54/46 вместо прежних до 95/5.
- Случай 6 vs 13 при baseline +1.00: −0.33 → **27/73 short** (было 58% long).
- Дашборд: в предложении «как посчитано» теперь есть потолок, вес, конфликтное правило,
  флип-гард и пометка «бэктест не нашёл у baseline преимущества». То же в «Exact formula»,
  например `factors −0.37 (L 6 · S 13) ×0.9 · baseline +0.50 (raw +1.00, cap ±0.5)
  ×0.1→0 (clear tally against it) → net −0.33 → p_long 26.9`. Старые результаты без новых
  полей показываются прежним текстом.
- Тесты (`tests/test_analyst_calibration.py`): случай 6 vs 13; знак сплита никогда не против
  перевеса на сетке 0..13 × 0..13 с сильным long/short/без baseline; симметрия; границы;
  сумма 100; нейтральная полоса; baseline один не выходит из полосы; флип-гард.

## FIX 2: EMA как на графике

- `indicators_section` считает ленту с периодами графика: по умолчанию 7/14/21. Поля
  `ema_periods`, `ema_fast`/`ema_mid`/`ema_slow`, `ema_stack`, `ema_note`; `ema200` без изменений.
- Клиент отправляет `ema_periods` из настроек ленты (`getActive().emaPeriods`). Сервер
  проверяет: 1–3 целых 2..400, иначе 400. Периоды входят в ключ кэша сервиса и в ключ
  анализа на клиенте. После смены ленты показанный анализ помечается устаревшим
  («analysis is for BTCUSDT 15m · EMA 7/14/21 — re-analyze»).
- Промпт просит называть в тексте факторов периоды из `indicators.ema_periods`.
- Обратная совместимость: карточка Trend и `analyst.ema_ribbon()` читают и старую форму
  (`ema7/ema14/ema28`, `ema_stack_7_14_28`) из старых/кэшированных результатов. Цитаты
  `indicators.ema28` в старых логах просто не разрешаются в значение, ошибки нет.

## Ограничения

- Бэктест проверяет только детерминированную часть. Факторы LLM исторически не
  переигрываются, а 12 живых анализов — только ориентир.
- Replay baseline отличается от боевого: Binance вместо Bybit-first свечей; цена = close
  бара, а не live last price; funding = последний расчётный Binance, а не прогноз Bybit.
  Не восстановлены OI change, стакан HL, taker ratio, ликвидации, опционы и корреляция с BTC:
  истории нет, поэтому код оценки считает их нейтральными. Соседние бары зависимы (горизонты перекрываются).
- Порог `conflict_min_agent` 0.15 и вес 0.1 выбраны из условия «baseline без преимущества
  не должен выводить из нейтральной полосы», а не подгонкой по выигрышам: данных для
  подгонки нет.
- Схема БД не менялась, `ema_periods` в лог не пишутся (они есть в снимке и его хэше).
- Лента отправляется целиком, все три периода, даже если одна линия скрыта на графике.
