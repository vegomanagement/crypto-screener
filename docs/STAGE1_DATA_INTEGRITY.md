Ветка: `claude/research-data-integrity`.
База: `8434f8d8169eb61dbce4e8f085c55a922238bee4`.
Изменения локальные: push/deploy и подключение торговых ключей не выполнялись.

## Что изменено

- Live-адаптеры Bybit/Binance/Hyperliquid сохраняют реальные `ts` открытия и `close_ts`, источник, инструмент, таймфрейм и turnover при наличии. Возвращаются только закрытые свечи; открытый хвост не используется для подтверждённых сигналов.
- `market_candles.py` проверяет OHLCV, конечность значений, положительные цены, объём, отсутствие дубликатов/разрывов. Пропуски не заполняются вымышленными барами.
- `/api/klines` больше не вычисляет timestamps от времени HTTP-запроса; возвращает источник. Неизвестные interval отклоняются до сетевого вызова, также в `/api/zones`.
- VWAP использует реальные UTC-сессии по timestamp, а не число последних строк. API перестал терять существующие MTF/OI/VWAP из-за несовместимых ключей.
- Исторические snapshots допускают HTF только после закрытия, решение датируется close основного бара. Funding/OI и сессия привязаны к этому времени.
- Изменение за 24 часа и OI lookback используют elapsed-time lookup; кеши проверяют хвост и разрывы. Источник сохраняется при парсинге новых данных; для старого кеша не выдумывается.
- Walk-forward сохраняет необходимый предшествующий HTF/event контекст без включения будущих закрытий.
- Общий paper-execution kernel для tracking/backtest проверяет midpoint touch до выхода. TP до исполнения входа не считается прибылью.
- Явная новая политика выхода: полный выход на TP1. Неопределённость внутрисвечного порядка — `ambiguous`, R неизвестен, а не фиктивный 0R. Неполная история — `censored`; отсутствие исполнения в полном горизонте — `unfilled`.
- Tracking не использует экстремумы до активации сигнала, обрабатывает доступную историю перед expiry и хранит execution metadata в существующем JSON без миграции SQLite.
- Realized R рассчитывается по геометрии entry/exit, backtest fee — по notional обеих сторон. Gap через стоп учитывается по доступной open-цене.

## Что эта версия НЕ доказывает

- Это paper model, не наблюдаемое реальное исполнение ордера. Midpoint touch не моделирует очередь/частичное исполнение; fill_ts — начало свечи, не точный момент сделки.
- Funding cashflows, spread, полноценное slippage и портфельные ограничения ещё не реализованы; live tracking R остаётся gross.
- Старые исторические TP2/TP3/tie результаты не переписаны. Новые результаты с политикой TP1 нельзя напрямую сравнивать со старой статистикой.
- Остались отличия live/replay feature calculations; этап не объявляет их полностью идентичными.
- На expiry между границами свечей точное исполнение может остаться неизвестным; отсутствие полной истории не превращается в 0R.
- Fallback сохранён для совместимости, но provenance теперь виден. Строгое закрепление площадки и registry точных контрактов — следующий отдельный шаг.
- Безопасный UI-only launcher остаётся локальным audit-инструментом. Промышленный startup, webhook authentication, Telegram allowlist и outbox ещё не исправлены. Не выставлять этот сервис наружу как готовый hardened production.
- EMA-профиль 7/14/28/200 и дальнейшее улучшение интерфейса не добавлены. Kronos и новые веса не установлены.

Следующий порядок: закрыть ingress/lifecycle и контракты данных, затем общий профиль признаков D1/4H, после этого Kronos shadow-worker и независимая оценка.
